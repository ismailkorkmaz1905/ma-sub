## Confirmed defects repaired

Ranges below refer to the repaired source in this report's commit. Each issue was traced to its production caller. Tests replace GPU or remote service boundaries where necessary, not every downstream validator.

### P1-01: Missing speech never reached recovery in delivery-first

- Source: `src/mas/engine/delivery_coverage.py:49-67,108-240`; `src/mas/delivery_first.py:367-466`.
- Trigger: primary ASR contains no cue in a region found by independent VAD, a caption hint, or an incomplete primary segment. The prior delivery-first worker went straight to alignment and translation without testing those gaps.
- Impact: a missing conversation could remain blank without a targeted decode.
- Repair: subtract retained cue intervals from the hint inventory, decode only uncovered windows without ASR's VAD filter, and merge only audio-derived results inside the owned window. Captions select audio but never supply dialogue. Existing primary text is not overwritten.
- Bounds: 10,000 ms per target, 20 seconds per request, 180 seconds of shared episode recovery, at most 192 jobs, no mandatory-work exemption, and the 1,800-second delivery reserve. Completed or interrupted targets are not silently relaunched. Remaining gaps are explicitly reported, not converted into a whole-episode failure.
- Evidence: `test_gap_plan_catches_vad_hole_and_joint_vad_asr_miss_with_caption_hint`, `test_recovery_uses_owned_audio_result_and_reuses_completed_jobs`, `test_default_worker_recovers_detected_gap_then_freezes_real_id_pack`.
- Limit: this proves routing, ownership and resume, not that Whisper recognized every real word. If ASR, VAD and caption hints all miss speech, no independent ground truth has been established.

### P1-02: Empty dialogue and continuous speech could stop first-hour delivery

- Source: `src/mas/engine/part_scope.py:91-161`; `src/mas/engine/part_audio.py`; `src/mas/delivery_first.py:176-239,367-466`.
- Trigger: no safe boundary exists near the first hour, VAD returns a legitimate empty inventory, or all cues in one part are unusable.
- Impact: the old planner/schema requirement stopped the entire episode before export.
- Repair: an explicit EP14+ delivery boundary policy chooses an available nearby gap or a bounded cut; every source sample remains owned exactly once. Evidence crossing a forced boundary is clipped into its corresponding child ranges, with a boundary warning. A genuinely empty scope produces an authenticated empty-subtitle export, not invented dialogue or a fake translation handoff.
- Evidence: `test_continuous_speech_or_empty_vad_cannot_deadlock_first_hour`, `test_no_dialogue_scope_reaches_authenticated_export_without_translation_handoff`, existing real PCM part tests.
- Limit: forced cuts can bisect dialogue; this is warned rather than described as acoustically safe. Empty delivery explicitly reports the absence of usable subtitles and is not quality PASS.

### P1-03: Public checksums could self-authorize part publication and worker ACKs

- Source: `src/mas/partial_delivery.py:63-144,147-204`; `src/mas/engine/partial_encode.py:154-213`; `src/mas/delivery_first.py:58-74`.
- Trigger: a retained delivery-first export is real, but its subsequent encoding/publication/ACK records are forged and their public checksums recalculated.
- Impact: the worker could accept self-asserted publication evidence and skip the first part.
- Repair: delivery-first encoding, publication and ACK records have purpose-separated HMAC authentication. Whether authentication is mandatory is determined from the authenticated export, not a removable quality label in the supplied receipt. Publication still originates only after actual remote byte/SHA readback in the publisher.
- Evidence: `test_rehashed_controller_ack_cannot_skip_first_part`, `test_part_publication_and_encoding_reject_unsigned_self_asserted_receipts`, existing full-delivery tests.
- Trust boundary: this protects artifacts against changes without the external key. It does not attest a malicious runtime that already possesses that key.

### P1-04: Valid new exports were rejected by collection retry

- Source: `src/mas/runpod_controller.py:1665-1712`.
- Trigger: result collection fails after a delivery-first export is created; retry still expects `strict-partial-subtitles`.
- Impact: no progress after the expensive work has completed.
- Repair: permit the precise new export mode for EP14+ only after authenticating its signature and checking its owned file inventory.
- Evidence: `test_real_delivery_export_authorizes_collection_retry_not_forged_export`.

### P1-05: The compute deadline also prevented retained local delivery

- Source: `src/mas/runpod_controller.py:1179-1268`.
- Trigger: encode or upload must resume after the original six-hour episode budget expired.
- Impact: already prepared outputs could never be delivered through the normal resume path.
- Repair: a separate bounded 3,600-second local delivery retry is allowed for retained delivery-first exports, after the existing release/export/encoding checks. The original episode clock is never rewritten and no Pod is authorized. A separate record states `SLO_MISSED`.
- Evidence: `test_expired_compute_budget_permits_only_retained_local_delivery`.
- Limit: this is not extra GPU time or proof the four/six-hour target was met. Missing translation or unprepared later parts still cannot be invented by a local upload retry.

### P1-06: Drive initiation and preservation interruption traps

- Source: `src/mas/remote.py:269-312,315-564`; `src/mas/drive_resumable.py:117-126,168-431`.
- Triggers: the old-file move has not created the retained directory; OAuth fails before upload initiation; the create response is lost; or a resumable session expires.
- Impact: a stale started flag or ambiguous session could block every later retry even when no bytes had been sent or the existing temporary object was recoverable.
- Repair: create the owned retained directory before listing it; persist private PREPARED intent before setting the controller's started flag; pre-generate and persist a Drive file ID before create. Reconcile that exact ID/name/parent on retry. An expired session may restart only for the owned temporary object. A completed object is not retransmitted. Wrong ownership, forbidden access and legacy ambiguous sessions without a reserved ID remain errors.
- Evidence: tests in `tests/test_drive_resumable.py` cover lost create response both before and after server creation, completed-response loss, expired session, changed parent ownership, PREPARED interruption and byte offset resume. `tests/test_delivery.py` covers a genuinely absent retained directory rather than assuming an empty listing.
- Readback distinction: upload metadata alone is not delivery PASS. `upload_verified` still reads all bytes of the remote temporary/final object and compares SHA-256.
- Protocol basis: Google's pre-generated ID documentation specifies idempotent create retries and HTTP 409 on an already created ID. Its resumable upload documentation requires restarting expired sessions. These docs were checked; no live Google operation was made.

### P2-01: CTC corrections were clipped back to inaccurate coarse bounds

- Source: `src/mas/engine/delivery_align.py:88-109,143-227`.
- Trigger: accepted acoustic timing starts 100 ms before or ends 100 ms after the original coarse interval.
- Impact: the refinement was accepted but the correction was discarded by clipping it back to the old timing.
- Repair: preserve the accepted CTC cue bounds within the existing 500 ms outward limit and preserve the original interval in provenance. No far-scene drift, timing invention or score relaxation is introduced.
- Evidence: `test_real_ctc_interval_is_not_clipped_back_to_inaccurate_coarse_bounds` plus existing bounded worker and overlap tests.

### P2-02: Delivery's signed wrapper did not bind the real primary model

- Source: `src/mas/delivery_first.py:367-466`; `src/mas/engine/delivery_coverage.py:70-74`.
- Trigger: the same model name is used with changed weight files or decoder/producer environment, while an older signed delivery schema exists.
- Impact: early schema reuse could bypass the authenticated primary reader's current model check.
- Repair: bind the actual model and producer identity into the signed primary/schema context before any cache hit. Check the actual primary result identity before signing its wrapper.
- Evidence: `test_changed_actual_model_rejects_frozen_schema_before_another_model_call`, `test_changed_primary_identity_is_not_signed_as_current_result`.

### P2-03: An encode exception could delete the only completed temporary video

- Source: `src/mas/engine/partial_encode.py:18-27` and its encoder workspace call.
- Trigger: encoding has produced bytes, then a later validation/receipt step raises before normal publication.
- Impact: TemporaryDirectory cleanup removed the only output copy.
- Repair: retain the temporary encoded bytes on every exception. Existing authenticated pending receipts remain the authority for automatic reuse; an unverified file is not relabeled complete.
- Evidence: `test_encoder_workspace_preserves_media_on_post_encode_validation_failure`.
- Limit: completion before durable checkpoint is inherently ambiguous; this fix preserves evidence, not an exactly-once guarantee across every possible process kill.

### P2-04: ID ZIP validation decompressed before enforcing workload bounds

- Source: `src/mas/engine/id_translation.py:774-805`.
- Trigger: oversized or highly compressed input reaches `testzip()` before any resource guard.
- Impact: avoidable memory/CPU consumption or a validation stall.
- Repair: reject more than 2,048 members, more than 16 MiB for one member, or more than 64 MiB total uncompressed bytes before CRC/decompression. Normal translation packs retain the same identity checks.
- Evidence: `test_id_zip_size_guard_runs_before_crc_or_decompression`.
