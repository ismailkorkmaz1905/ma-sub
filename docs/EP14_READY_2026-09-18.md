## Changes

### Cleanup is independent of new-work prerequisites

The controller owns failure cleanup from immediately after acquiring its local
process lock. On an exception, an existing unresolved capacity journal is
validated before any provider operation. Cleanup requires only the external API
key and valid ownership evidence, not a fresh price quote, clean checkout, image,
SSH key or remaining work budget. It cannot create a new Pod. Existing protected
and unrelated Pods remain untouched. Wrong episode, altered ownership, missing
key or unverified provider absence produces `EXTERNAL CLEANUP REQUIRED`, not a
safe-retry instruction.

A resumed lease no longer needs the 300-second new-start reserve. It still needs
its shutdown reserve and cannot extend the original episode/provider deadline.
A resume-only plan cannot acquire new capacity. Termination and absence polling
share a separate 120-second cleanup allowance. A lost DELETE response is resolved
through external absence observation, never assumed to be success. When the API
or credentials are unavailable, manual external intervention remains necessary.

### Controller readiness and Windows environment

`mas.ps1` reloads missing process values for `MAS_RUNPOD_IMAGE`,
`MAS_RUNPOD_STORAGE_QUOTE`, execution/priority and episode budget from Windows
User environment. Existing process overrides are retained. A quote must still
be a real observation no older than 24 hours; do not edit its timestamp to bypass
validation.

Normal `doctor` returns nonzero for missing tools or Torch; it is inventory, not
production certification. The controller-specific check does not demand local
CUDA. It verifies Git/environment/keys, configured image-digest syntax, the storage
quote, a real synthetic QSV probe when selected, read-only Drive readiness and
reports free bytes. It does not resolve/pull an image, test real GPU inference,
prove episode disk sizing or start/stop any Pod.

### First published part, local tails, then one full file

EP14+ delivery-first publishes part-001 and requires real remote byte/SHA-256
readback. Later parts are encoded after verified GPU release, retained locally
and acknowledged through a separate signed `controller-tail-ack` contract.
`LOCAL_ENCODED_NOT_PUBLISHED` is not a publication receipt. The worker may advance
on that authenticated local completion; the controller always revalidates the
actual files before full assembly. A local-tail ACK cannot skip part-001 or relax
strict EP12/13 delivery. Previously published tail receipts remain valid and their
remote objects are not deleted.

The full assembler accepts every exact planned sample range once, in order,
from published part-001 and verified locally encoded tails. It stream-copies
compatible burned streams. Assembly is checkpointed before full upload; a failed
upload retries without another encode/join. Both existing full-file readbacks and
old-object preservation remain. There is no `COMPLETE_PARTS` shortcut to full
publication. Normal new delivery transfers only first-part plus full MP4, rather
than all separate tails plus full MP4.

### Validation I/O and visible quality

On POSIX, a single export-validation call hashes a given parent file only once,
using an in-call map bound to expected digest/size and device/inode/size/mtime/ctime. It is
not a process-global cache. Independent validation calls before/after encoding
or upload reread bytes. File disappearance, mutation and symlink/path escape
remain errors. Windows retains full reads because Python 3.11 ctime represents
creation time rather than metadata-change time; the repair does not pretend to
have safely eliminated local Windows rereads. Protocol reference:
https://docs.python.org/3.11/library/os.html#os.stat_result

`status 14` shows small authenticated stored quality, local-tail and full-delivery
metadata. It explicitly labels this as stored evidence, not live service or large
artifact revalidation. Missing/changed signatures never become PASS. The quality
summary exposes empty subtitles, omitted cues, unresolved hint interval count and
duration in milliseconds. Hint coverage is not independent speech ground truth.

Delivery-first quality warnings remain non-blocking; no new linguistic gate,
CPU ASR fallback, translation API or invented dialogue is added. Empty usable
ASR can still yield an honestly labeled empty-subtitle export. Inspect the real
source before deciding that such a result is usable. `NOT_STRICT` and
`NOT_ASSERTED` perceptual acceptance remain separate from transport success.
